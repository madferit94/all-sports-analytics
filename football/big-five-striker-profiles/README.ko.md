# 유럽 5대 리그 스트라이커 데이터 — 2025/26

[English](README.md) | [한국어](README.ko.md)

비페널티 슈팅 빈도와 슈팅당 평균 기회 품질을 비교하기 위해 수집한 Understat 데이터입니다. 수집 코드, 시즌 범위로 정리한 CSV, 원본 파일의 해시와 검증 기록을 제공합니다. 전체 원본 응답은 로컬 캐시에 보존합니다.

## 문제와 분석 질문

득점 수에는 슈팅 기회의 양, 슈팅 선택과 마무리 결과가 함께 반영됩니다. 초기 스카우팅 비교를 위한 질문은 다음과 같습니다.

> 중앙 공격수 후보 중 누가 비페널티 슈팅을 자주 기록하며, 누가 슈팅당 더 높은 xG의 기회를 얻거나 선택하는가?

xG는 각 슈팅이 득점으로 이어질 가능성을 추정한 값입니다. 두 축으로 슈팅 빈도와 모델이 추정한 평균 기회 품질을 구분하고, 서로 다른 유형의 선수를 선정해 경기 맥락을 추가 검토하려 합니다. 선수의 전체 능력이나 영입 적합성을 확정하는 지표는 아닙니다.

**현재 단계:** 데이터 수집과 검증 완료. 산점도 분석, 경기 맥락을 고려한 해석과 스카우팅 결론은 다음 단계입니다. 아래 숫자는 데이터 확보 현황이며 축구 분석 결과가 아닙니다.

## 수집 범위와 행의 기준

- 리그: 프리미어리그(`EPL`), 라리가(`La_liga`), 분데스리가, 세리에 A(`Serie_A`), 리그 1(`Ligue_1`).
- 시즌: **2025/26**. Understat에서는 시작 연도인 `2025`로 표시합니다.
- 5개 리그 요약표에 있는 모든 선수를 보존합니다.
- 상세 수집 대상은 원천 포지션 표기에 `F`가 포함된 선수와 `S`만 있는 선수입니다. `S`만 있는 선수는 선발 포지션이 불명확하므로 검토 대상으로 남겼습니다. 수집할 때는 최소 출전시간을 적용하지 않았습니다.
- 이 조건 밖 선수는 시즌 요약만 있습니다. 모든 선수의 슈팅 이벤트를 수집한 데이터는 아닙니다.
- 선수 원본 응답에는 과거 시즌도 포함됩니다. 분석용 CSV는 5개 리그의 2025/26 경기 ID 목록으로 범위를 제한합니다.
- 같은 리그 안에서 이적한 기록은 원천 요약에 합산돼 있습니다. 다른 리그로 이적한 기록은 리그별 행으로 남습니다. 기본 대상 181행에서는 고유 선수 수도 181명이지만, 기준을 바꾸면 같은 선수가 여러 행에 나타날 수 있습니다.
- 선수당 점 하나로 합칠 때는 슈팅 수·xG·출전시간을 먼저 합산한 뒤 비율을 다시 계산해야 합니다. 90분당 지표를 단순 평균하지 않습니다.
- 이름으로 연결하지 않고 원천 선수 ID와 경기 ID를 사용합니다. 원천 이름, 팀명과 포지션 표기를 보존합니다.
- 재실행 시 기존 원본 파일을 덮어쓰지 않습니다. 다른 시점의 데이터를 수집하려면 새 폴더에서 시작합니다.

## 중앙 공격수 후보 선정 기준

리그 요약의 `F M S` 같은 표기만으로 중앙 공격수를 구분하기는 어렵습니다. 상세 경기 기록의 `FW`, `FWR`, `FWL`, `AMC` 등을 사용해 다음 기준을 적용했습니다.

1. `Sub`로 기록된 출전시간은 실제 역할을 알 수 없으므로 중앙 공격수 시간으로 추정하지 않습니다.
2. `Sub` 이외의 포지션이 기록된 시간이 전체 출전시간의 50% 이상이어야 합니다.
3. 그 시간 중 정확히 `FW`로 기록된 시간이 50% 이상이어야 합니다.
4. 기본 산점도에는 추가로 리그 출전시간 900분 이상, 비페널티 슈팅 1회 이상, 모든 대조 검증 통과 조건을 적용합니다.

이 분류는 **중앙 공격수 후보**입니다. 경기 포지션 표기는 실제 경기 중 역할을 분 단위로 추적한 기록이 아닙니다. 슈팅과 90분당 지표에는 다른 포지션으로 출전한 경기도 포함합니다. 50%와 900분 기준은 분석을 위한 선택이며 Understat의 공식 기준이 아닙니다.

포지션 근거가 부족한 `insufficient_known_position`, 측면 공격수·혼합 역할에 해당하는 `other_forward_or_mixed_role`도 검증표에 남아 있습니다. 포지션 근거 부족은 낮은 경기력을 뜻하지 않습니다.

## 두 축의 정의

```text
비페널티 슈팅 수 = situation != 'Penalty'이고 result != 'OwnGoal'인 이벤트 수
비페널티 xG 합계 = 위 이벤트들의 xG 합계
X축 npshots_per90 = 비페널티 슈팅 수 / 리그 출전시간 × 90
Y축 npxg_per_shot = 비페널티 xG 합계 / 비페널티 슈팅 수
npxg_per90        = 비페널티 xG 합계 / 리그 출전시간 × 90
```

성공·실패 여부와 관계없이 모든 페널티 슈팅을 제외합니다. `OwnGoal` 이벤트는 `counts_as_attempt=False`로 남기고 공격 슈팅 수와 xG 합계에서 제외합니다. 원천 이벤트 목록에는 xG가 0인 자책골이 들어 있지만 선수의 공격 슈팅 합계에는 포함되지 않는 점을 대조 과정에서 확인했습니다.

코너킥, 다른 세트피스와 직접 프리킥은 포함합니다. 따라서 비페널티 슈팅은 오픈플레이 슈팅과 다릅니다. 분모가 0이면 CSV 셀을 비워 두며 0으로 대체하지 않습니다.

`npxg`는 원천 요약값이고 `shot_sum_npxg`는 같은 제공자의 슈팅 이벤트에서 다시 합산한 값입니다. 두 값은 절대 허용오차 `0.0001`로 비교했습니다. 슈팅 수가 0이 아니면 다음 관계가 성립해야 합니다.

```text
npshots_per90 × npxg_per_shot = npxg_per90
```

평균 슈팅 xG는 모델이 추정한 기회 품질입니다. 마무리 능력이나 선수 개인의 인과적 기여를 직접 측정하지 않습니다.

## 검증과 원천 중복 문제

검증 대상은 경기 수와 종료 여부, 선수·리그 및 선수·경기 키의 중복, 슈팅 ID 중복, 슈팅과 출전 기록 연결, 좌표·xG의 `[0, 1]` 범위입니다. 시즌 요약과 상세 기록의 출전 경기 수·출전시간·슈팅 수·xG·비페널티 xG·득점·비페널티 득점을 대조하고 포지션별 시간 합계도 확인합니다.

2026년 4월 23일 Real Oviedo–Villarreal 경기(`29482`)에서 수집 대상 12명에게 `roster_id`만 다른 출전 기록이 두 건씩 있었습니다. 원천 시즌 출전 경기 수와 출전시간 합계에도 추가 기록이 반영돼 있습니다.

원본과 원천 시즌 요약값은 보존했습니다. `player_match_records.csv`에서는 가장 작은 roster ID의 기록을 한 건 남기고, 중복 내역은 별도 파일에 기록했습니다. roster ID 이외의 값도 다른 중복이라면 임의 선택하지 않고 수집 처리를 중단합니다.

영향을 받은 12개 선수·리그 기록은 `no_source_duplicate_appearances` 검증에 실패하며 기본 산점도에서 제외했습니다. 중복 처리 후 출전 경기 수와 시간은 `unique_appearance_count`, `unique_appearance_minutes`로 따로 확인할 수 있습니다. 실패한 행의 지표를 검증된 값으로 사용하면 안 됩니다. 중복 처리만으로 다른 원천 통계의 정확성이 보장되지는 않습니다.

이 검증은 같은 제공자 데이터 사이의 내부 일관성을 확인한 것입니다. 모든 경기 이벤트의 사실 여부나 xG 모델의 정확도를 독립적으로 검증한 것은 아닙니다. 리그 수준, 팀 점유율, 전술 지시, 경기 상황과 동료의 기회 제공 수준도 보정하지 않았습니다.

## 실행 방법

Python 3.11 이상에서 표준 라이브러리만 사용합니다. 추가 패키지 설치는 필요 없습니다.

이 프로젝트 폴더에서 공개 CSV를 검증하려면 다음을 실행합니다. 다운로드 없이 `csv_verification.json`을 생성하며 최초 원본 검증 기록은 보존합니다.

```bash
python3 verify_saved_data.py
```

새 시점의 데이터를 수집하려면 `collect_understat.py`와 `verify_saved_data.py`를 새 빈 폴더에 복사하고 실행합니다.

```bash
python3 collect_understat.py
python3 verify_saved_data.py --verify-raw
```

새로 받은 응답은 공개한 스냅샷과 다를 수 있습니다. 기존 로컬 수집을 이어가려면 그 수집 폴더에서 수집 코드를 다시 실행합니다. 저장된 원본은 재사용하고 분석용 CSV는 다시 만듭니다. 최초 스냅샷의 원본 해시를 검증하려면 당시 원본 캐시가 필요합니다.

수집은 작업 스레드 2개, 전체 요청 간격 제한, 제한된 재시도와 원본 캐시를 사용합니다. CSV는 스프레드시트에서 열기 쉬운 UTF-8 BOM 형식입니다. `data/raw/**/*.meta.json`에는 출처 URL, UTC 수집시각, 응답 메타데이터와 해시를 기록합니다.

수집 주소는 사이트의 `league.min.js`, `player.min.js`에서 확인한 읽기용 주소입니다. 안정성을 보장하는 공개 API 문서가 있는 인터페이스는 아니므로 사이트 변경 시 코드 수정이 필요할 수 있습니다.
