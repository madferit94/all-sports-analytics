# 전체 경기 이동 영상 따라가기

[English](v4_replay_guide.md) · [한국어](v4_replay_guide.ko.md)

두 선수가 같은 시각에 서킷의 어디에 있었는지 전체 51랩에서 확인합니다. 98분 02.755초의 경기 구간을 기본 24배속, 20fps로 재생해 MP4 길이는 4분 05.2초입니다.

1. `outputs/ko/v4/replay.html`을 여세요. 랩 선택, SC1·SC2·마지막 랩 이동, 12·24·48배속을 사용할 수 있습니다.
2. 반복 제작은 `python scripts/ko/v4_full_race_replay.py`로 실행하세요. 원본이 없으면 `--fetch-missing`을 붙입니다. 기존 원본은 보존합니다.
3. 단계별 학습은 `notebooks/ko/v4_full_race_replay.ipynb`에서 Run All을 누르세요. 기본 실행은 대표 프레임 3개를 새로 그립니다. `RENDER_FULL_VIDEO=True`로 바꾸면 전체 영상도 다시 만듭니다.

## 데이터와 검증

전체 API 응답은 선수마다 37,095개 표본입니다. 요청에는 경기 전후 표본도 포함되어 있어 원본은 그대로 보존하고, 경기와 경계 보간용 표본만 선수마다 22,538개 사용합니다. 51개 모든 랩에 위치 표본이 있습니다. 최대 표본 간격은 1.339초이며 비교 구간 내 시간 중복·좌표 결측은 없습니다.

영상의 두 점은 같은 UTC 시각으로 맞춥니다. 표본 사이를 직선으로 보간하되 간격이 2초를 넘으면 점을 숨깁니다. 경기 자체에는 이런 공백이 없었으며, 별도의 인위적인 20초 공백 검사에서 점이 숨겨지는지 확인했습니다. 지도 윤곽은 러셀 29랩의 위치 궤적입니다. 정밀 주행 라인이나 코너별 좌우 위치를 복원하지 않습니다.

VER→RUS 격차는 OpenF1 시간 차이 표본입니다. 지도상 두 점 사이 거리를 시간 차이로 바꾸지 않습니다. 12초가 지난 표본은 비워 두며 값 아래에 표본의 경과 시간을 표시합니다. 최종 공식 결과 **VER +0.196초**는 따로 고정 표시합니다. 마지막 랩 종료 추정 시각과 시간 차이 갱신 시각이 달라 마지막 재생 표본은 0.237초일 수 있습니다. 이것을 최종 결과로 해석하지 않습니다.

SC 음영 끝은 다음 선두 랩 시작을 이용한 후보입니다. 실제 철수 확정 시각이 아닙니다. 타이어 사용량은 스틴트 시작 시 사용량으로, 현재 사용량이나 마모를 뜻하지 않습니다.

## 각 함수가 하는 일

| 함수 | 목적 |
|---|---|
| `download_locations` | 없는 원본만 수집합니다. |
| `load_replay_inputs` | 드라이버·유일키·시간·원본 해시·51랩 범위를 검증합니다. |
| `build_replay_frames` | 같은 프레임 시각에 두 차량 위치·랩·최신 시간 차이를 연결합니다. |
| `save_replay_tables` | 랩별 표본 수·프레임별 위치·검증 결과를 저장합니다. |
| `make_frame_renderer` | 서킷과 차량 점·랩·타이어 맥락·타임라인을 그립니다. |
| `render_video` | MP4를 인코딩하고 모든 프레임을 다시 읽어 확인합니다. |

연속 전체 재생은 MP4이며 GIF는 전체 구간에서 고른 80개 프레임의 약 14초 요약입니다. 기존 29–33랩 V2 영상과 V1–V3 분석 파일도 유지했습니다.

출처: [OpenF1 location 문서](https://openf1.org/docs/#location). [원본·프레임 검증](../data/processed/v4/replay_audit.json) · [실행 확인](v4_execution_check.json).

영상 랩 이동에는 바이트 구간 응답이 필요합니다. 프로젝트에서 `python src/serve_replays.py --port 8767`을 실행하고 `http://127.0.0.1:8767/outputs/ko/v4/replay.html`로 여세요. 기본 `python -m http.server`는 영상 탐색을 충분히 지원하지 않습니다.
