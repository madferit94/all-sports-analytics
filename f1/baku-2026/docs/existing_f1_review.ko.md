## 확인한 문제

1. **같은 경기 팀 동료 결과의 누수:** 변수 생성 노트북의 0부터 센 12번 셀 `add_team_features`는 시즌·팀별 드라이버 행을 한 **행**씩 이동합니다. 같은 경기 앞 행의 팀 동료 결과가 경기 전 변수에 들어갈 수 있습니다. 저장 CSV에서 2016년 1라운드 Haas의 GRO가 8점을 얻었는데 같은 첫 경기 GUT의 `team_points_before=8`, `team_points_last_3=8`입니다. 팀·경기별 한 행으로 먼저 집계하고 경기 단위로 이동한 뒤 두 드라이버에게 연결해야 합니다.
2. **한 바퀴 뒤진 완주를 DNF 처리:** 자료 준비 노트북 9번 셀은 상태에 `Finished`가 없으면 DNF로 처리하고 완주 순위를 지웁니다. 저장 CSV에서 `+N Lap(s)` 형태이며 DNF=True인 행은 전체 **7,572개**, 2016년 이후 **1,260개**입니다. 이 상태는 뒤처진 완주를 나타내며 반드시 리타이어를 뜻하지 않습니다. 원본 정의로 완주·신뢰성 정답을 다시 구성하고 원래 순위를 보존해야 합니다.
3. **경기 후 결과로 평가 대상을 선정:** 승리 모델은 완주 순위 결측과 그리드 0을 제외합니다. 2024년 저장 변수는 **479행**인데 필터 후 **284행**입니다. 경기 전 예측은 결과와 독립적인 참가자 집합과 피트레인 출발 처리 원칙이 필요합니다. 뒤의 Top-10 코드도 이 필터가 적용된 `train_df`·`valid_df`를 재사용하고 변수 결측을 추가 제외해 앞선 전체 참가자 블록과 평가 집합이 다릅니다.
4. **재현 경로:** 첫 노트북에 `/Users/.../Desktop/F1_analysis` 고정 경로가 있습니다. 첫 셀의 일반 `pip install kagglehub`는 보통 Python 커널에서 유효한 코드가 아닙니다. 프로젝트 상대 경로·고정 원본·별도 설치 안내 또는 `%pip` 셀로 바꿔야 합니다.
5. **설명 과장:** 운영 준비 완료, 누수 방지, 차량 기여도의 수치, 전략의 인과적 조언은 이 코드만으로 뒷받침되지 않습니다. 연도별 검증은 좋은 시작이지만 누수·정답·참가자 범위·경기별 우승자 평가·확률 보정이 먼저입니다. SHAP은 모델의 관련성을 보여주며 공학적 원인을 증명하지 않습니다.
