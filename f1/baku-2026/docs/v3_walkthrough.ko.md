# V3 분석 따라가기

[English](v3_walkthrough.md)

**목표:** 최종 격차가 작으면 경기 내내 비슷하게 빨랐을까요? 모델부터 생각하지 않고 이 질문을 따라갑니다.

1. 공식 시간 차이 곡선을 보고 같은 시각에 SC·피트 기록을 붙입니다. 피트레인 통과가 곧 타이어 교체는 아닙니다.
2. `driver_lap_exclusions.csv`를 읽습니다. 드라이버·랩 하나마다 시작·종료 시각과 맥락, 제외 이유가 있습니다.
3. `paired_lap_audit.csv`를 읽습니다. 같은 랩의 RUS·VER 랩타임을 연결하고 한 명이라도 제외되면 쌍을 제외합니다. SC 경계가 후보이므로 적격 여부 이름도 `candidate_pair_eligible`입니다.
4. `candidate_pace_summary.csv`에서 VER−RUS 중앙값·표본 수·IQR(가운데 50% 값의 범위)을 읽습니다. 양수면 러셀이 빠릅니다. 각 랩의 차이를 먼저 계산합니다.
5. `sensitivity_summary.csv`에서 황색기 겹침 랩 포함/제외와 시간 구간 ±1초 결과를 봅니다. 비교 구간의 기준 시각도 경계와 함께 이동합니다. 최소 5개 쌍은 표시 규칙이지 신뢰 보장이 아닙니다.
6. 타이어 사용 구간을 붙입니다. 새 구간의 시작 사용량이 반드시 0은 아닙니다. 이 비교로 독립적인 타이어 효과를 추정하지 않습니다.

## 함수별 역할

| 함수 | 어디에 쓰는가 |
|---|---|
| `load_and_validate` | 원본 보존, 조인·ID·랩 시작/종료 차이·선두 식별 검증 |
| `build_candidate_periods` | SC 투입/복귀 예고 연결, 황색기 보수적 시간 구간과 충돌 기록 |
| `select_candidate_pairs` | 두 선수 모두에 시간 겹침·피트·재출발·시각·타이어 구간 규칙 적용 |
| `summarize_pace` | 같은 랩 차이의 중앙값·IQR 계산 |
| `sensitivity_check` | 미리 정한 제외 규칙을 바꾸어 표본 수·결과 변화 확인 |
| `plot_results` | 시간 차이·후보 페이스·타이어 차트 저장 |
| `save_results` | 원본 해시·공지/시간 차이 연결·제외·요약·차트 저장 |

## 제외 이유 읽기

- `LAP_1`: 출발 랩.
- `PIT_LANE_RECORD` / `PIT_OUT_LAP`: 피트레인 기록·출차 랩.
- `SC_TIME_OVERLAP`: 해당 랩 시각이 SC 후보 구간과 겹침.
- `YELLOW_TIME_OVERLAP`: 어느 섹터든 황색기 후보 구간과 겹침.
- `CANDIDATE_RESTART_LAP`: 재출발 후보 랩.
- `TIMING_END_START_MISMATCH`: 추정 랩 종료와 다음 실제 시작의 차이가 허용 범위 초과.
- `STINT_CONTEXT_UNRESOLVED`: 타이어 구간 연결이 미매칭·다중 매칭.

## 중요한 범위

실제 주석 코드가 들어 있는 학습용 노트북입니다. 위에서 아래로 모든 셀을 실행하세요. 두 언어의 CSV 컬럼과 API 공지 문자열은 계산 비교를 위해 영어로 유지하고 설명·주석·차트는 번역했습니다.

다른 경기에서 VSC·RED 공지가 발견되면 이 코드는 중단합니다. 다른 경기의 해당 구간 처리는 구현하지 않았으므로 모든 경기용 판정 엔진은 아닙니다. 황색기 섹터는 3개 타이밍 섹터와 같다고 가정하지 않습니다. CLEAR가 없는 구간은 검토 대상으로 남기며 시간 겹침이 실제 차량 영향을 증명하지 않습니다.

재출발·깃발 검토 전 결과는 잠정입니다. 원본과 V1·V2는 보존했습니다. V3는 저장된 원본에서 바로 실행할 수 있습니다.
